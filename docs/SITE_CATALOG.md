# Shared site catalog 1.0.0

Production entry point: `web/public/sites.json` (served as `/sites.json`). This
catalog contains real terrain assets and sourced conditions, not Tim's synthetic
`sites.example.json`. Source choices are in `scripts/catalog/selection.py`.

The per-location delivery checklist is in [LOCATION_HANDOFF.md](LOCATION_HANDOFF.md),
generated by `python -m scripts.catalog.handoff` from the production catalog.

## Integration

Eyad: import `loadCatalog` and `mapFeatures` from `/catalog-loader.mjs`.
Filter GeoJSON points by `body` before displaying on a body-specific basemap;
Moon/Mars coordinates are not Earth WGS84. `bbox` is raster outer bounds.
Coordinates are east-positive, -180..180; Moon/Mars latitude is planetocentric.

Tim: `await loadCatalogTerrain(site, origin)` returns the existing `SiteTerrain`
shape. It uses the existing Kilbourne `createTerrainData` loader to validate
binary samples and flips north-first rows once to south-first, keeping west-first
columns. Elevations remain absolute metres; the physics grid uses its default
centered origin. A scalar annual wind speed cannot populate a directional wind
vector. The standalone map loader does not create wind or friction overrides.

All catalog adapters preserve the entire site under `site.catalog.record`.
This includes `classification` (morphology, substrate, atmosphere, slope class,
roughness class and annual temperature class), `identifiers`, all `conditions`,
`comparison_features`, `feature_measurements`, resources, footprints, terrain
provenance, completeness, limitations and `simulation_defaults`. Null values and
their reasons remain intact. No fields are reduced to a single wind-speed value.
Related comparison records are in `site.catalog.pairings`. Pass the catalog as
the third argument of `loadCatalogTerrain(site, origin, catalog)` to include them
in the standalone map adapter. The TypeScript physics adapter includes them when
its catalog argument is provided. Explicit viewer analog scenarios also expose
`site.catalog.target` as a separate complete planetary record.

Select a real site in the viewer to inspect **Site categories and conditions**.
Expand any section for values, units, status, provenance and missing-data reasons,
or download the complete site record. These properties remain metadata unless
the physics adapter explicitly uses them; temperatures are not a thermal model.
Tim's adapter maps albedo and substrate to its existing simulation inputs. Scalar
wind is applied only when the caller explicitly supplies `windTowardDeg`; no wind
direction is assumed by default. Sun elevation is an equinox-noon scenario approximation. These
assumptions are shown separately from the observational record.

The TypeScript adapter additionally exposes the full separately ingested seasonal
profile under `site.catalog.environment.profile` for Kilbourne, Meteor, Amboy,
Badwater, White Sands and Barrow. Its baseline is **2015–2024**, kept distinct from
the catalog's 2024 means. All months, seasons, scenario rows, radiation, soil context,
unknown mechanics and sources are preserved. The explicit ID join is in
`app/sim/src/catalog-environment.ts`; other sites return an unavailable status with
a reason. The viewer displays and downloads this profile too. These fields do not
automatically override physics; Tim's existing seasonal adapter can select a period.
The standalone map adapter preserves the catalog record but seasonal profiles must
still be loaded through `app/lib/environment.mjs` as described in
[environment integration](environment-integration.md).

The physics viewer loads `/sites.json` through `app/sim/viewer/catalog.ts`.
Vite serves `web/public` so catalog and terrain URLs work in development and
production builds. Run `npm ci` then `npm run viewer` from `app/sim`.
The site selector includes each catalog site with terrain in its native body
environment, plus explicitly labelled Earth/planetary analog scenarios from
`pairings`. Analog scenario IDs are `<earth_id>--<planetary_id>`; they use the
Earth terrain and the target body's simulation environment, not the target's
terrain or measured local weather. Native IDs remain unchanged.
The viewer uses `terrainPackToSite` to flip north-first samples exactly once.
No friction, cohesion or density measurements are inferred from substrate labels.
Tim's existing plume/dust interpretation remains a simulation model.
Adding a site with a valid terrain manifest to the catalog requires no viewer
code change. Failed catalog requests appear in the viewer error message. Individual
missing or failed terrain packs appear as disabled options with reasons; other sites
continue loading. Haughton and Qaidam now load real Copernicus packs. If absent from a deployment, they remain disabled with a reason. Pairing
options are labelled proposed analogs, not validated scientific matches.

All packs support the existing JS geometry loader, so extra GLBs and PNGs are
unnecessary. Kilbourne's original pack is preserved. New packs contain compact
float32 grids, GeoTIFFs, manifests and checksums. Full planetary mosaics are not
downloaded or committed: GDAL requests source windows over HTTP ranges.

## Condition vocabulary

These are engineering catalog categories, not natural universal thresholds.
Version changes require a schema/method version change.

| Field | Definition |
|---|---|
| morphology | crater (origin further identified), impact_crater, volcanic_plain, lava_field, dune_field, canyon, rocky_desert, delta, playa, polygonal_ground |
| substrate | basalt, basaltic_sand, gypsum_sand, sedimentary_rock, evaporite, permafrost, icy_regolith, lunar_regolith, unknown |
| slope_p95_class | level: [0,5) degrees; gentle: [5,15); steep: [15,30); very_steep: [30,90] |
| roughness_3km | low: [0,10) m; moderate: [10,50); high: >=50; RMS height about local mean in 3x3 cells at 1km spacing |
| atmosphere | terrestrial, thin_co2, airless; body-level context, not local measured pressure |
| annual_air_temperature | freezing_mean: <0 C; cool_mean: [0,15); warm_mean: >=15; only 2024 mean 2m air temperature, not climate-zone classification |
| resources | unknown unless a footprint-specific abundance measurement exists; regional ice evidence is described separately from local confirmation |

Interpretations retain their source URL. `feature_measurements` lists desired
crater/dune/polygon identifiers whose numeric values are not yet supported.
Quantities carry value, unit, status, source, resolution, time coverage, method,
caveat and missing reason. Status is measured, derived, modeled, assumed, unknown,
or not_applicable. Null does not mean zero. Lunar atmospheric wind and 2m air
temperature are not_applicable. Lunar surface temperature is a distinct quantity.
Substrate never supplies friction, cohesion or density. Simulation assumptions
belong only in `simulation_defaults`, currently empty for every site.

## Footprints and selection

Earth squares span 4.8km between outer sample centres at 30m spacing. These are
reproducible regional crops around the listed centres, not mapped feature
boundaries or surveyed control points. Meteor's centre is offset west by about
0.5km to avoid a tile boundary while retaining crater and ejecta context.
Moon crops span 4.8km at 150m output spacing; Mars crops span 16km at 500m.
Pixel edges extend half a sample beyond these dimensions. The local projections
are UTM on Earth and body-specific azimuthal equidistant on Moon/Mars.
LOLA's stored 0.5 scale is applied before export. Copernicus uses EGM2008 heights,
MOLA uses areoid heights, LOLA uses a 1737400m reference sphere. Absolute elevation
is never compared across bodies.

Selected Earth sites: Kilbourne, Meteor Crater, Amboy, White Sands, Badwater,
Barrow Observatory, Craters of the Moon, Lava Beds, Capitol Reef, Haughton and Qaidam. This expands
the original 6–8-candidate scope to include the user's additional selections.
Capitol Reef is explicitly a candidate sedimentary-relief analog, not a newly
discovered or validated Jezero match. A regional square mixes geological units.

Other evaluated candidates: Cima field (NPS monogenetic volcanic-field overview)
and Sunset Crater/San Francisco volcanic field (NPS Geodiversity Atlas). Both
are defensible volcanic candidates but were deferred because Amboy, Craters of
the Moon and Lava Beds already cover that class; impact, salt, dune and icy
terrain provide greater variety. Their exclusion is not a scientific rejection.

Seven planetary research targets: Jezero delta neighbourhood, Bagnold regional dune
context, Arsia flank, Phoenix northern plains, Marius Hills volcanic terrain,
Shackleton northern rim, and Lucus Planum yardangs. None is certified safe for landing. The original broad
Arsia lava-tube entry is narrowed to a volcanic study area without claiming an
identified cave. Shackleton is a local rim crop, not the previous all-longitude
polar cap. Phoenix adds an icy/periglacial comparison for Barrow.

## Similarity method 1.0.0

Each terrain is area-averaged onto exactly 1km cells in a centered 4x4km square.
Mean slope uses metre gradients. Roughness is mean local RMS over only interior
3x3 windows (3km support); it includes regional slope, not detrended rock texture.
Relief is max-min of the same 4x4km grid. Export spacing is never advertised as
native resolving power. Common spacing reduces scale mismatch but does not
remove sensor, interpolation, DSM/DTM or latitude-dependent sampling differences.

For each feature d=min(abs(a-b)/scale,1). Contributions are weight*(1-d).
Weights: slope .4, roughness .4, relief .2. Fixed scales: 15 degrees, 150m, 1000m.
All three compatible derived features are required. Otherwise terrain_score=null
and coverage is the sum of available feature weights. No reweighting or ranking
inflation for sparse sites. Adding sites does not change normalization.

Pairings are geological/process hypotheses supported by site descriptions; the
numeric score measures terrain descriptors only. A high score can occur for
different geological origins. No environmental or combined score is calculated
until compatible observations exist on both bodies. These are engineering
comparisons, not validated mission suitability or landing safety assessments.

## Rebuild and validation

Python environment: install `requirements-dev.txt` and `Pillow>=11,<13`.
The existing environment used Python 3.14, Rasterio 1.5.2, NumPy 2.5.4 and
SciPy 1.18.1; use these versions when byte-level reproduction matters.

```powershell
.venv/Scripts/python -m scripts.catalog.build
.venv/Scripts/python -m scripts.catalog.build --offline
.venv/Scripts/python -m scripts.catalog.validate
.venv/Scripts/python -m pytest -q --basetemp=.test-tmp-catalog
node scripts/catalog/check-consumers.mjs
node scripts/terrain/check_loader.mjs
.venv/Scripts/python scripts/terrain/validate_kilbourne.py
```

`--site ID` retrieves and records one site in ignored cache; rerun the full build
to publish it into the local catalog. Cache is `data/cache/catalog` and is not
committed. Raw weather responses and source-window hashes support reproduction.
The build writes `data/catalog-run-report.json` with precise failed stages;
failures are retained as explicit missing catalog assets and cause a nonzero
exit. Inspect this report and run validation before consuming rebuilt data.
No commits, merges, pushes or deployment are performed by these commands.

## Haughton and Qaidam terrain additions

The catalog now includes eleven Earth sites and seven planetary sites. Both new
Earth packs use real Copernicus GLO-30 elevation, 161 × 161 north-first float32
samples at 30 m output spacing, and selected 4.8 km windows. Native source windows
and receipts are retained alongside the output for reprocessing. Licence and
attribution follow the existing Copernicus contract.

- `haughton`: 75.37 N, 89.68 W, a floor study window within the Haughton impact
  structure on Devon Island, Canada. The proposed Shackleton comparison includes
  explicit matches and differences; a floor crop is not a lunar rim replica.
- `qaidam`: 38.66 N, 93.27 E, a published multilayered-yardang location in Qinghai,
  China. The window replaces the earlier broad basin placeholder. A proposed
  Lucus Planum yardang pairing is supplied with a real coarse MOLA terrain window.

Coordinates designate processing windows, not safe landing points. Source DSM
sampling is approximately one arc-second north/south; longitude sampling changes
with latitude (notably Haughton). Small rocks, narrow yardang walls, ground ice and
engineering soil properties remain unresolved. 2024 NASA POWER context is supplied;
these additions do not have the separate 2015–2024 seasonal profiles.

Rebuild only the additions, preserving all existing catalog records:

```sh
python -m scripts.catalog.build --site haughton
python -m scripts.catalog.build --site qaidam
python -m scripts.catalog.register --site haughton --site qaidam
python -m scripts.catalog.handoff
python -m scripts.catalog.validate
node scripts/catalog/check-consumers.mjs
```

Registration validates the complete staged snapshot and resulting catalog before
enabling a site. It rejects unexplained checksum mismatches. Existing elevation
bytes and hashes are preserved. See [transactional build and recovery commands](CATALOG_PUBLICATION.md).

Evidence: [NASA Haughton field report](https://ntrs.nasa.gov/citations/20060013129)
and [Qaidam yardang field study](https://doi.org/10.1029/2018JE005719).

## Complete pairing explanations and strict missing-data policy

Every enabled Earth record now has `pairing_notes`, mirrored in each pairing's
`explanation`: explicit matches, differences, source links, scope and
`proposed_unvalidated` status. The source of these explanations is
`scripts/catalog/pairings.py`, shared by full builds and incremental registration.
Adding a pairing requires providing its explanation. No validated similarity,
engineering transfer or landing certification is implied by a terrain score.

Qaidam now pairs with `lucus-planum`: a 16 km study window centred on NASA/JPL
THEMIS image PIA24008 at latitude -1.61604, east longitude 187.227 degrees
(stored as -172.773 degrees). THEMIS imagery documents wind-eroded yardangs;
MOLA at roughly 463 m native postings supplies regional context. The 33 × 33,
500 m output does not reconstruct individual yardang walls. Substrate, local
material properties and environmental similarity remain unresolved.

Evidence: https://www.jpl.nasa.gov/images/pia24008-lucus-planum-yardangs/
Earth field context: https://doi.org/10.1029/2018JE005719

The old USGS mosaic host returned HTTP 403 during acquisition. The source URL
recorded for Lucus is the public USGS `asc-mars` S3 distribution of the same MOLA
mosaic. Saved native source samples, scale/offset receipt and hashes are included.

Both `terrainPackToSite()` and `profileToSite()` reject missing or nonfinite
heights. The JSON importer additionally rejects malformed or invalid supplied
roughness layers, and no longer fills missing elevations with the mean. Missing
optional roughness is left absent. There is no automatic synthetic replacement.

Reproduce the new target and register it with the updated Qaidam record:

```sh
python -m scripts.catalog.build --site lucus-planum
python -m scripts.catalog.build --site qaidam
python -m scripts.catalog.register --site lucus-planum --site qaidam
python -m scripts.catalog.handoff
```
